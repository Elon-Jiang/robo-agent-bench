# Designing discrimination in embodied-agent benchmarks

Research snapshot: November 7, 2026. **Recommendation: combine meaningful task composition, held-out variation, and reliable outcome verification; do not equate lower scores with better discrimination.** The near-ceiling local pilot is user-reported, not independently re-evaluated here. No benchmark was rerun. Numbers below are reported results or explicitly labelled calculations/proposals. Extrema refer to the cited cohort, not universal rankings. Policy-training results establish design precedents, not predicted LLM-agent performance.

**Benchmark evidence.** “No formal ladder” means the source defines task families or experimental conditions, not ordered difficulty levels. Percentages denote success unless another metric is specified.

| Benchmark | How difficulty is constructed; scoring; observed separation |
|---|---|
| **LIBERO** | Spatial varies relational grounding among otherwise similar objects; Object varies object identity; Goal varies objectives with shared objects/layouts. These are capability axes. LIBERO-90 contains shorter tasks; Long contains longer compositions. Spatial/Object/Goal/Long each contain **10** tasks; **90** supplies the larger pretraining collection. Binary predicate success is averaged over rollouts; the original lifelong-learning study additionally measures forward transfer, forgetting, and learning-curve area over **3** training seeds. [Original paper, §4–5/App. D](https://arxiv.org/html/2306.03310). In the published MemoryVLA comparison, Spatial best/worst is **98.4/74.3** (MemoryVLA/MaIL), Object **98.8/85.2** (π₀/TraceVLA), Goal **96.4/68.3** (MemoryVLA/Diffusion Policy), Long **93.4/50.5** (MemoryVLA/Diffusion Policy), and LIBERO-90 **95.6/46.2** (MemoryVLA/SpatialVLA). Training histories and observation inputs differ. [MemoryVLA Table 3](https://shihao1895.github.io/MemoryVLA/static/files/MemoryVLA_paper.pdf) |
| **LIBERO-PRO** | Perturbs object appearance/size, initial positions, instruction paraphrases, target/action combinations, and environments; preserves feasibility and excludes invalid combinations. No universal easy/hard ladder. Binary success, **50** episodes/task. Goal-suite original best/worst: **98/92** (OpenVLA/π₀); position-perturbed: **38/0** (π₀.₅/OpenVLA and π₀). Thus robustness changes the ranking; some perturbations instead collapse nearly everyone to the floor. [Paper §4–5, Table 2](https://arxiv.org/html/2510.03827v1) |
| **LIBERO-Plus** | Adds layout/distractors, cameras, robot starts, language, lighting, backgrounds, sensor noise; tests combinations too. Instance difficulty **L1–L5** means solved by **4/3/2/1/0** reference models, respectively—empirical labels, not physical thresholds. Baseline original max/min **97.6/76.5** (OFT_m/OpenVLA); filtered Plus max/min **70.0/17.3** (OFT/OpenVLA), using binary success. Post-trained result **79.6** belongs to a separate intervention. Filtering removes easy instances, so difficulty-label separation on the labelling models is partly circular; retain an independent audit cohort. [Paper Tables 1–2, App. C](https://arxiv.org/html/2510.13626v1) |
| **CALVIN** | ABCD→D includes the test environment during training; ABC→D holds out environment D, changing scene appearance/layout. Execute **5** language tasks consecutively without resetting; score successful-prefix length, equivalently the sum of probabilities of completing each prefix. Evaluation uses **1,000** chains. In GR-1’s comparison, average-length best/worst: ABCD→D **4.21/0.40**, ABC→D **3.06/0.31** (GR-1/MCIL). Held-out full-chain success is **40.1%/0%**. Chaining exposes compounding failures hidden by single-action success. [GR-1 §4/Table 1/App. A.2](https://gr1-manipulation.github.io/static/paper.pdf) |

Pick-can best/worst: VM **85.7/2.7** (RT-1 converged/beginning), VA **89.8/0.6** (RT-1 converged/Octo-Base). Randomization need not lower the strongest score. Calibration matters: physically mismatched controls or appearances can create misleading spread. [Paper §IV–VI, App. D Table IV](https://arxiv.org/html/2405.05941) |
| **RoboTwin 2.0** | Explicit **Easy=clean**, **Hard=domain-randomized** clutter, lighting, background textures, table height; language variation is another supported axis. Paper protocol trains each task on **50 clean demonstrations**, evaluates **100 rollouts/condition**, and averages binary success across **50 tasks**. Easy best/worst **55.2/28.0** (DP3/DP); Hard **16.3/0.6** (π₀/DP). This measures clean-to-random robustness; do not mix with training on randomized demonstrations. [Paper §4.5/Table 5](https://arxiv.org/html/2506.18088) |
| **RoboCasa / RoboCasa365** | Original **25 atomic/75 composite** kitchen tasks compose picking, appliance operation, and cleanup into everyday activities; changing kitchens and objects adds generalization. The successor separates Atomic-Seen, Composite-Seen, Composite-Unseen, with the latter withholding task compositions from pretraining—not merely unseen kitchens. Task-averaged binary success. Current non-agentic cohort max/min: Atomic **86.5/15.7** (Awomo-0.5I or Axiom-0/DP), Composite-Seen **60.4/0.2** (Awomo-0.5V/DP), Composite-Unseen **45.2/1.1** (Awomo-0.5I/π₀). | **ManiSkill3** | No universal difficulty ladder: task families, state versus visual observations, object/pose randomization, embodiments, contact precision, and task-specific horizons. **Transferable non-robotics designs.**

- **GAIA:** levels use annotator effort: L1 generally at most **1 tool/5 steps**, L2 roughly **5–10 steps** with multiple tools, L3 unrestricted sequences. Exact-answer scoring. Original L1 model range **9.1–30.3%** (GPT-4/GPT-4+plugins), but all model baselines score **0** on L3, versus humans **87.3%**: a warning about floor effects, not successful strong/weak separation at every tier. [Paper §3/Table 4](https://arxiv.org/html/2311.12983)
- **SWE-bench:** Lite’s **300** cases reduce evaluation cost through filtering; Verified’s **500** cases prioritize solvability. They are not adjacent difficulty tiers. Verified separately labels estimated repair effort; easy **<15 minutes**, hard **>1 hour**. Hidden regression and repair tests prevent “fix one thing, break another.” GPT-4 Lite scores vary **2.7–28.3%** across scaffolds; exact best/worst by effort bucket is **UNVERIFIED** here. [Lite](https://www.swebench.com/lite.html), [Verified methodology](https://openai.com/index/introducing-swe-bench-verified/)
- **τ-bench:** final database-state correctness plus policy constraints. `pass@k` rewards any successful attempt; `pass^k` requires every attempt to succeed, estimated per task before averaging. Retail pass¹ spans **61.2/14.8%** (GPT-4o/Llama-3-70B); GPT-4o pass⁸ falls below **25%**. Domain tracks are not difficulty levels. [Paper Table 2/§5](https://arxiv.org/html/2406.12045)
- **OSWorld:** human-time bins Easy **0–60s**, Medium **60–180s**, Hard **>180s**; GPT-4V/SoM scores **16.78/13.12/4.59%**. These are one-model tier results; cross-model tier extrema are **UNVERIFIED**. Execution-based evaluators, observation modalities, cross-app workflows, and action budgets expose different bottlenecks. [Original paper §5.1](https://arxiv.org/html/2404.07972)

**Technique catalogue.** Costs below are engineering estimates relative to an existing MuJoCo task, not published timings. Evidence refers to the linked comparisons above.

| Technique | Evidence and users | Implementation cost |
|---|---|---|
| Capability suites / semantic subsets | LIBERO, EmbodiedBench: different subset winners reveal distinct weaknesses. | Low: instruction variants and balanced sampling; manual ambiguity audit. |
| Composition / uninterrupted chains | CALVIN, RoboCasa: atomic competence fails to guarantee complete workflows. | Medium: dependency graph, reusable skills, terminal predicates. |
| Held-out generalization | CALVIN ABC→D, RoboCasa Composite-Unseen, VLABench categories. | Medium: disjoint generators/assets; track leakage. |
| Matched perturbations and combinations | PRO, Plus, RoboTwin: ranking changes under positions, cameras, clutter. | Low for poses/light; medium for collision-valid clutter and recovery. |
| Abstraction / observation ablations | CaP, ManiSkill: oracle/high-level conditions can mask grounding failures. | Medium: separate API contracts and equal controller quality. |
| Partial credit and reliability | BEHAVIOR, VLABench, AA; τ-bench and CodeActionBench expose incomplete or inconsistent solutions. | Low–medium for scoring; repeated rollouts increase evaluation cost. |
| Efficiency and uncertainty | AA, CodeActionBench, BEHAVIOR; [rliable](https://github.com/google-research/rliable) recommends interval estimates and performance profiles. Efficiency reveals differences when success saturates; a causal improvement in accuracy spread is **UNVERIFIED**. | Low instrumentation; medium statistical/evaluation cost. |

**Recommended MuJoCo recipe — proposed design, not validated results.**

Use **three tiers**, inspired by [CALVIN](https://arxiv.org/html/2112.03227v2) and [RoboCasa](https://arxiv.org/html/2406.02523): Foundation—atomic actions with clear instructions; Workflow—dependent household/business outcomes; Robust Workflow—the same goals under held-out variations and recoverable disruptions. Keep semantic, visual, precision, and horizon tags orthogonal to tier labels.

For spill cleanup: Foundation wipes an exposed spill; Workflow retrieves the sponge, clears an obstruction, cleans, restores objects, and parks the sponge; Robust Workflow changes object identities/layouts, partially occludes the spill, or shifts an object during execution. Parallel families could pack an order, prepare a serving tray, or sort office supplies. Choose obstruction counts, reach distances, contact tolerances, and budgets from oracle feasibility sweeps and functional requirements. Use explicit success tolerances; distinguish resolvable implicit intent from genuinely ambiguous requests. Vary factors individually before combining them.

Hold the public tool API fixed across tiers. Separately ablate oracle state versus RGB/depth, and generic Cartesian/gripper tools versus semantic macros, following [CaP](https://arxiv.org/html/2603.22435v1). Exclude task-solving helpers. Hold harness and budget constant when attributing differences to models. Count simulated execution inside generated programs, alongside charged calls, inference cost, and wall time.

Report task-macro-averaged strict success as the primary endpoint; terminal progress, constraint violations, chain length, and reliability alongside it. For partial credit, normalize completed required outcomes and expose components; prerequisite-gate milestones and penalize collateral damage. Preserve reversible requirements at termination, optionally after a settling check. Avoid a composite score that lets cheap movement substitute for useful completion. Freeze tier weights before testing.

**Sampling:** proposed screening uses **20 distinct layout seeds/task**; a main comparison starts at **100**, using matched seeds across agents. These are planning choices, not guaranteed separation. From [NIST’s Wilson/sample-size guidance](https://nvlpubs.nist.gov/nistpubs/TechnicalNotes/NIST.TN.2119.pdf), calculated worst-case **95%** Wilson half-widths at success probability **0.5** are about **±13.4/9.6/4.9 percentage points** for **50/100/400** independent episodes. The planning approximation `n≈z²p(1−p)/e²` gives **385** for **±5 points**. Precision of one proportion is not power to distinguish two agents: plan around a prespecified meaningful difference and pilot paired-outcome variance.

Separate scene seeds from repeated stochastic agent attempts. Bootstrap paired score differences, preserving task/seed/repeat nesting; report per-task intervals and a task-stratified aggregate interval, following [rliable’s statistical guidance](https://proceedings.neurips.cc/paper_files/paper/2021/hash/f514cec81cb148559cf475e7426eed5e-Abstract.html). If intervals do not establish separation, report insufficient evidence of a difference or collect a preregistered larger sample; overlapping uncertainty does not establish equivalence. Many repeated runs of one scene do not establish generalization.

**Failure modes and repairs.**

- **Ceilings and floors:** Plus filters easy cases; PRO and ManiSkill show that excessive difficulty can floor everyone. Calibrate for reproducible strong–weak gaps, not merely low average scores, on diverse baselines; then freeze the test set and audit with models excluded from selection. Preserve an easy anchor.
- **Impossible or underspecified tasks:** Verified screens descriptions and tests; CodeActionBench verifies reference solutions within budgets and removes arbitrary shoe/arm assignments. Validate every generated layout physically and ensure observations contain enough information. [Verified](https://openai.com/index/introducing-swe-bench-verified/), [CodeActionBench App. A](https://arxiv.org/html/2609.33807)
- **Latched success:** CodeActionBench replaces transient success with terminal checks for persistent outcomes; event tasks retain event records plus final obligations. A completed wipe may remain completed, but restored mugs and sponge release must still hold. [Verifier design](https://arxiv.org/html/2609.33807)
- **Noisy graders, cheating, and drift:** OSWorld-Verified repairs ambiguous tasks and brittle evaluators; EmbodiedBench fixes false navigation success and versions old datasets. Isolate evaluator/state access from agent code, hide oracle scripts, replay suspicious successes, distinguish infrastructure errors from scored failures, and version fixes. These isolation measures are recommendations, not a claim that all surveyed benchmarks prevent cheating. [OSWorld repair report](https://xlang.ai/blog/osworld-verified), [EmbodiedBench changelog](https://github.com/EmbodiedBench/EmbodiedBench)
